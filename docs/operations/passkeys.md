# パスキー運用・利用者と管理者の手順

v2.0.0の[認証仕様](../architecture/authentication.md)に従う。User／Group Adminはパスキー必須、Portal Adminはパスキーまたはパスワード＋TOTPを使用する。クラウド同期は全ロールで禁止。

## 端末の準備

配布PCでPIN・指紋・顔認証等の端末本人確認を設定する。同期しない端末固定型パスキーを登録できるOS／ブラウザーを使用する。証明書・hosts／DNSは[構築手順](../deployment/setup.md#ローカルhttpsと初回端末準備)に従い、信頼済みHTTPSと固定ホスト名で接続する。IPアドレス直打ち、HTTP、証明書警告を無視した接続はパスキー用に使わない。

## 利用者：初回登録とログイン

1. 管理者からユーザー名と30分有効の登録コードを、承認済みの社内手段で受け取る。
2. ログイン画面の「初回登録・管理者による再登録」(`/passkeys/enroll`)へ進む。
3. ユーザー名、登録コード、重複しないPC名を入力し「このPCに登録」を押す。ブラウザー／OSの案内で、このPCのPIN・指紋・顔認証を行う。
4. 登録後はログイン画面へ戻る。ユーザー名を入力し「パスキーでログイン」を押す。通常ログイン用password／TOTPは一般ユーザーへ発行しない。

登録コードは登録成功で1回だけ消費する。登録成功だけではEC2／DCV操作はできず、パスキーでのログインが必要。PINや生体情報はPortalへ送らない。

## 利用者：複数PC・交換・紛失

1ユーザーに最大10台分を登録できる。別PCは管理者へ追加登録コードを依頼して、各PCで同じ初回登録手順を行う。認証方式を変更する必要はない。既存キーは残る。コードは同時に1つで、再発行すると旧コードは無効。

「パスキー」(`/passkeys`)でPC名と登録日時を確認する。ログイン後10分以内ならこのPCへ追加登録・不要キーの削除が可能。削除後は全Portalセッションが失効し再ログインする。最後のキーは本人が削除できない。PC紛失時は管理者へ連絡し全キーをリセットしてもらい、必要な各PCへ再登録する。予備キーの登録は必須としない。

## 管理者：登録・追加コード発行

Portal Adminとしてログイン後10分以内に `/admin/users` を開く。新規User／Group Adminの登録時には登録コードを1回だけ表示する。既存ユーザーや追加PCには「パスキー登録・リセット」で対象ユーザーと本人確認・発行理由を入力し「登録コード発行」を押す。コードの有効期限は30分。画面を閉じた後は再表示しない。

期限が切れたコードは再発行する。渡す先の本人確認は組織の手順に従い、コードを共有ログ・メール代替の個人サービスへ貼り付けない。Portal Admin本人のパスキーも同じ登録経路またはログイン後の追加登録で設定できる。

## 管理者：紛失時のリセット

本人確認と原因調査を行い、対象と理由を入力して「全パスキーをリセットして発行」を押す。対象の全キー・未完了登録／認証・未使用DCV tokenを削除し、旧Portalセッションを失効する。表示された新しい登録コードを本人へ渡し、各PCで再登録する。既存DCVのOSセッション終了は行わない。

無効なアカウントは別途再有効化し、30日期限切れは先に再有効化する。最終ロックは理由付きのロック解除が必要。待ち時間中は期限まで待つ。リセット・コード発行でロック／待ち時間は解除しない。

## ローカル管理CLI

Portalを停止し、DBをバックアップした保守時間に実行する。AWS基盤管理者の権限で操作し、実行者・理由をOS／運用記録にも残す。一般ユーザーにSSM対話アクセス、SSH／RDPを許可しない。

```sh
./awsportal-admin -db /var/lib/awsportal/awsportal.db -cmd create-user -user user01 -role user
./awsportal-admin -db /var/lib/awsportal/awsportal.db -cmd invite-passkey -user user01 -reason '本人確認済み・追加PC'
./awsportal-admin -db /var/lib/awsportal/awsportal.db -cmd reset-passkeys -user user01 -reason '本人確認済み・PC紛失'
```

各コマンドは登録コードを表示する。`invite-passkey`は既存キーを保持、`reset-passkeys`は全キーを失効。CLI操作の監査actorは `local-maintenance`。全Portal Adminが使えない場合は[Break-glass](password-recovery.md#portal-admin)でpassword＋TOTPを復旧し、パスキーを再登録する。

## 問題の対処

| 状況 | 対処 |
|---|---|
| パスキーを利用できない | 固定HTTPS名・CA信頼・OS本人確認・ブラウザー対応を確認。同期型ではなくPC内の端末固定型を使用 |
| 登録できない | PC名の重複／10台上限、コード期限、無効／期限切れ／ロック／待ち時間を確認 |
| 操作がキャンセルされた | 認証器の案内に従って再試行。キャンセルだけで失敗回数は増えない |
| 設定変更／追加／削除を拒否された | ログインから10分を超えていればログインし直す |
| ホスト名変更後に使えない | RP IDが変わるため、新しい接続先で本人確認とコード発行・再登録が必要 |
