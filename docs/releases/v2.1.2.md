# v2.1.2

## 変更

- クイック導入ガイドを追加し、配布物の取得・検証、専用サービスユーザー、HTTPS、TOTP暗号鍵、初期管理者、初回ログインとDCV接続までを案内する。README・文書目次・構築手順から参照でき、リリースアーカイブにも同梱する。
- DCVリリース試験手順を現行版へ更新し、信頼済みHTTPS、管理者password＋TOTP、通常ユーザーのパスキー、操作単位の本人確認、監査の受入項目を記載する。
- github.comへ接続できない環境向けに、検証済み配布物・チェックサム・ラボ用ソースの搬入手順を追加する。非公開S3を使うラボでは本体とチェックサムそれぞれの署名付きURLを設定し、チェックサム検証を維持する。残る外部接続要件と資材の後片付けも記載する。
- ラボの既定配布URLと導入・試験例をv2.1.2へそろえる。Portal・管理CLIの認証・監査動作はv2.1.1の仕様を維持する。

## 更新・受入

1. 新規導入は[クイック導入ガイド](../deployment/quickstart.md)、一時ラボは[作成・試験・廃棄手順](../development/dcv-release-test.md)を使用する。Portal・管理CLI・DCV関連ファイル・ラボ用ソースは同じv2.1.2タグでそろえる。配布アーカイブにはlab/が含まれないため、ラボではソースも取得する。
2. 既存Portalの更新前はサービスを停止し、DB・設定・元のTOTP暗号鍵・旧配布物をバックアップする。DBと鍵は別に保管し、同じ鍵を維持する。旧版からの移行は[v2.1.0](v2.1.0.md#更新手順)と[v2.1.1](v2.1.1.md#更新受入)を先に確認する。
3. 公開チェックサムと配布物のSHA-256を照合し、Portal・管理CLIと必要な同梱ファイルを配置する。既存設定を維持してサービスを再起動し、HTTPSの/healthz、管理者ログイン、本人確認、DCV接続を確認する。
4. 旧ラボのUserData更新だけでは再導入されない。対象スタックを廃棄して作り直し、試験後はスタック削除と残存資源の確認を行う。搬入用S3資材はスタック外なので別途削除する。

## 検証

[必須テスト](../development/testing.md)に加え、導入・試験例のシェル構文、文書リンク、systemd設定、配布対象一覧とアーカイブの内容・チェックサムを確認する。リリース前にGo公式の安定版とgovulncheckを確認し、ARM64のPortal・管理CLIを再ビルドする。認証・監査の受入項目は[v2.1.1](v2.1.1.md#検証)を継続する。AWSリソースの作成、DCV画面操作、配布端末での実機受入は適用環境で実施する。
