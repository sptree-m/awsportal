# v2.1.0

## 変更

- Go 1.27.2へ移行し、CI・リリース・LabビルドのGo指定をgo.modへ集約する。AWS SDK S3/EventStream、x/crypto、x/sys、圧縮ライブラリをセキュリティ修正版へ更新する。
- PR #51のGo単体HTTPS既定化を収録する。TLS 1.2以上、設定不備時は起動を拒否する。リバースプロキシのHTTPバックエンドは明示設定を必要とする。
- Portal Adminのパスキーとpassword＋TOTPを維持する。User／Group Adminはパスキーのみ。TOTPの検証済み時間ステップをDBトランザクションで消費し、再利用と同時使用を拒否する。
- 全Cookie認証の更新操作へCSRF検証を適用する。重要な管理変更とMFA設定はログイン後10分以内に限定し、時間を過ぎた場合は両ログイン方式のどちらかでログインし直す。
- 認証APIの送信元別回数・同時実行数・保持エントリー数を制限する。ユーザー枠を占有する未完了ログインチャレンジは古いものを入れ替える。登録用チャレンジは保護する。
- ロック／無効化／セキュリティ復旧・パスワード変更時に旧セッションと専用トークンを失効させる。Proxy・Git・新規DCV認証でもロック状態を確認する。既存接続の切断はDCV Agent同期／Proxyトンネルの期限にも依存する。
- セッションの絶対期限8時間に加え、30分無操作で失効、1ユーザー5件・全体4096件の上限と定期削除を追加する。
- TOTP秘密情報をAES-256-GCMで暗号化し、DB・鍵ファイルを所有者限定にする。準備ファイルの認証前配布は維持する。
- PR・main・週次とリリース前にgovulncheckを実行する。

## 更新手順

1. Portalを停止し、DB・設定・旧配布物をバックアップする。旧DBのバックアップには平文TOTP秘密情報が含まれるため、暗号化・アクセス制限された保管先を使う。DB全体のVACUUMに必要な空き容量も確保する。
2. 同じv2.1.0タグのPortal・管理CLI・文書へ更新する。HTTPS直受けは`AWSPORTAL_TLS_CERT`／`AWSPORTAL_TLS_KEY`と固定`AWSPORTAL_WEBAUTHN_ORIGIN`を設定する。HTTPバックエンドは`AWSPORTAL_HTTP_MODE=http`を明示し、原則ループバック待受とする。
3. TOTPの鍵は`AWSPORTAL_TOTP_KEY_FILE`で指定できる。未指定ではDBのパスに`.totp-key`を付けた別ファイルへ初回生成する。鍵は32バイトのバイナリ・所有者限定0600の通常ファイルとし、DBバックアップとは別に安全に保管する。PortalとCLIで同じDB・同じ鍵設定を使う。保護した専用ディレクトリへ分離する場合は、事前に所有者専用ディレクトリを作成して鍵パスを設定する。
4. 起動時に既存TOTP秘密情報を暗号化し、VACUUMとWALの切り詰めで旧平文領域を除去する。アカウント・パスキー・割り当て・監査を保持する。暗号化済みDBに対応する鍵がない／鍵が違う／鍵権限が広い場合は起動を拒否する。鍵を再生成して回避しない。
5. nginxを使う場合は`proxy_set_header X-Real-IP $remote_addr;`を設定して、クライアントから来た値を必ず上書きする。信頼するプロキシは既定でループバックだけ。別ホストの場合は`AWSPORTAL_TRUSTED_PROXY_CIDRS`へそのプロキシの限定CIDRを指定する。`X-Forwarded-For`を認証制限の根拠にしない。
6. systemdで`UMask=0077`を設定し、DBディレクトリは専用ユーザー所有0700にする。HTTPS終端側でも接続元制限・本文サイズ・接続数制限を維持する。Agent APIの用途別経路制限は組織の承認済み構成で適用する。
7. 管理者の両ログイン、一般ユーザーのパスキー、管理変更、DCV、Proxy／Gitを受入確認する。ブラウザーを再読込し、新しいCSRF対応assetsを使用する。TOTPは直前に成功したコードを再利用せず、次のコードへ進んでから再ログインする。

鍵の紛失時は、バックアップした元の鍵と対応するDBをセットで復旧する。旧版へ切り戻す場合も停止して旧DB・旧設定・旧バイナリをまとめて戻す。暗号化後DBを旧版に渡さない。DBファイルだけの暗号化は稼働サービスアカウントの侵害を防ぐものではないため、OS・IAM・ネットワークの最小権限を維持する。

## 検証

CSRF・管理操作の再認証・TOTP同時再利用・認証枠占有・トークン失効・旧DB暗号化／鍵紛失・所有者の異なる暗号文・セッション上限を回帰試験する。既存の必須テスト、証明書検証付きHTTPS／明示HTTP実起動、ブラウザーのパスキー／管理者TOTP／htmx操作、ARM64・2 vCPU・1 GiB起動、govulncheckを確認する。実AWS／DCVと配布端末での受入は組織環境の適用時に行う。
