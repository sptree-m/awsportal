# v1.9.1

## 変更

- DCVの接続ポートを管理者が443・10443などに指定できる。PortalとDCVインストーラーの`AWSPORTAL_DCV_PORT`、Terraform root／shared-pilotの`dcv_port`を同じ値に揃える。既定8443を維持し、不正値と22・3389・内部認証用8444を拒否する。
- ラボの`DCVPort`をPortal・DCV待受・SG・接続先出力へ共通で反映する。既定のARM64配布物をv1.9.1へ更新する。
- **超軽量・高速・高いメンテナンス性・プロ仕様UI**を[READMEの最上位設計原則](https://github.com/sptree-m/awsportal/blob/v1.9.1/README.md#最優先のコンセプト)に明記する。文書整理でも削除・弱体化を禁止し、必須チェックで四つの方針・保持ルール・設計／UI文書からの参照の削除を検知する。
- 追加の実行時依存やDB移行はない。ネイティブ接続限定、ワンタイム認証、転送制限、軽量UIを維持する。

## 更新と設定

同じv1.9.1 tagのPortalバイナリ・DCVインストーラー・Terraform・文書を使用する。ポートを変更しない場合は既定8443で継続する。[443への設定と既存環境の切替手順](https://github.com/sptree-m/awsportal/blob/v1.9.1/docs/operations/dcv.md#接続ポートの指定v191以降)を参照。

接続ポートはPortal全体で共通。管理対象の全DCV EC2と通信許可を同じ値に揃え、保守時間にDCV／Portalを再起動する。提供済みSG・社内Firewall・NACLは管理者が更新する。内部認証8444やPortalのHTTPSポートは別設定として維持する。

Go・ARM64ビルド、DCV認証・設定生成、Terraformの指定ポートとCIDR、CloudFormationの設定連携を自動試験する。実AWSへの適用とDCVクライアントの接続・画面・入力は対象環境で確認する。
