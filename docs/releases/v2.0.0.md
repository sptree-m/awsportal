# v2.0.0

## 変更

- User／Group Adminの通常ログインを、本人確認必須・クラウド同期不可の端末固定型パスキーに限定する。既存のpassword／TOTPによる通常ログインを終了する。
- Portal Adminは同じパスキー、または従来のpassword＋TOTPを選べる。パスキーを使用する場合のTOTP追加入力は不要。
- PCごとの登録（最大10台）、30分・使い捨ての登録専用コード、管理者の理由付きリセット、旧セッション／未完了認証／未使用DCV tokenの失効を追加する。
- UV必須、BE／BS不可、固定Origin／RP ID、署名／challenge／counter、アカウント状態を検証する。既存の待ち時間・10回ロック・管理者解除・監査を維持する。ラボ用MFA迂回を終了する。
- Go SSR・SQLite・同梱assets・CSPを維持し、WebAuthn検証用Go依存と小さなローカルJavaScriptを追加する。64 IP対応の証明書・hosts台帳生成支援と管理者向けCA／配布／更新ガイドも収録する。仕様、初期設定、利用者・管理者・復旧・ラボのマニュアルを更新し、配布アーカイブに現行文書を含める。

## v1.xからの移行（認証の破壊的変更）

1. 配布PCで信頼済みHTTPS・固定DNS名・端末本人確認を用意し、同期しない端末固定型パスキーを登録できることを受入確認する。
2. 保守時間にPortalを停止し、SQLite DB・設定・v1.x配布物をバックアップする。同じv2.0.0 tagのPortal／管理CLI／文書を使用する。
3. systemdへ `AWSPORTAL_WEBAUTHN_ORIGIN=https://portal.company.example` を設定する。実ホスト名・ポートへ置き換え、パスや末尾スラッシュは付けない。未設定では起動しない。社内CAとHTTPS終端は既存の承認済み構成を利用する。
4. 起動時にpasskey／invite／challengeの3テーブルとusers.auth_generation列を追加する。既存ユーザー・割り当て・監査を保持する。一般ユーザーの旧passwordログインは即時拒否され、猶予モードは提供しない。
5. 既存Portal Adminはpassword＋TOTPでログインできる。停止中のCLIで `invite-passkey`、または再起動後のUsersで本人確認・登録コードを発行する。各ユーザーへ30分以内に渡し、各PCで登録後にパスキーログインする。無効・期限切れ・ロックは別途解除する。
6. 管理者の両認証経路、一般ユーザーのpassword拒否、複数PC、紛失復旧、同期キー拒否、権限制御・DCV・Proxy／Git専用tokenを受入確認する。

復旧が必要なら停止してバックアップ時点のDB・設定・バイナリをまとめて戻す。v1.xへ戻すと旧認証方式も戻るため、組織の承認を伴う保守操作として扱う。起動中DBへ旧版を上書きしない。

## 検証範囲

Go race・署名付き認証／登録応答・拒否ケース・アカウント状態・復旧競合、ARM64ビルド、Terraform／CloudFormation／DCVの既存必須試験、Chromium仮想認証器とConsoleの画面／CSP／ローカル資産を自動試験する。ARM64・2 vCPU・1 GiB制約試験は必須CIで確認する。

実配布PCのOS／ブラウザー／PIN・生体認証と社内CA、実t4g.microでの負荷・連続稼働、実AWS／DCVの受入を自動試験の成功で代替しない。詳細は[認証仕様](../architecture/authentication.md)、[パスキー運用](../operations/passkeys.md)、[復旧](../operations/password-recovery.md)、[構築](../deployment/setup.md)を参照。
